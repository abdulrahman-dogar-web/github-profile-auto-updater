# GitHub Profile Auto-Updater

Keep your GitHub profile README fresh — automatically. One command fetches
your live public repositories from the GitHub API and regenerates a complete
profile README: header, badges, stats cards, language breakdown, and a table
of your latest projects, sorted by most recently updated. Add a new repo,
re-run the script, and it shows up. No manual editing, no invented numbers.

## What it generates

Running `python3 update_profile.py` produces `PROFILE_README.md` with:

- **Header** — your display name, your real bio from GitHub, tagline, location, account age, and an "Open to work" line when your profile says you're hireable.
- **Badges** — shields.io badges for followers, public repo count, and total stars. The follower/repo badges are computed live by shields.io when the README loads; the star total is computed from the API response in the same run, so every number is real as of the last update.
- **Stats cards** — GitHub Readme Stats, Top Languages, and streak images (rendered live from your username and the theme in `config.json`).
- **Language breakdown** — counted from your actual repositories in this run, with a share bar per language.
- **Latest Projects table** — project name (linked), description, language, ⭐ stars, 🍴 forks, and last-updated date, sorted newest first. Forks are marked 🍴.
- **Social links** — only the links you fill in under `social` in `config.json`.
- **Last updated timestamp** — UTC, in the footer, so visitors can see how fresh the page is.

See a real one: [`example/PROFILE_README.md`](example/PROFILE_README.md) — generated by running this script against the live profile `abdulrahman-dogar-web` on 2026-11-08.

## Quick start

```bash
# 1. Clone / download this project and enter it
cd github-profile-auto-updater

# 2. Install dependencies (optional — the script runs on the standard
#    library alone and falls back to urllib if `requests` is absent)
pip install -r requirements.txt

# 3. Edit config.json — set your username, display name, bio and links
#    (it already ships configured for abdulrahman-dogar-web)

# 4. Generate your profile README
python3 update_profile.py
# ✅ Done — PROFILE_README.md updated with 6 latest projects.
```

That is the whole setup. Python 3.9+ is required; tested on Python 3.12.

### No token needed

Public repository data needs no authentication. If you run the script very
often, set a token for the higher rate limit (60 → 5,000 requests/hour):

```bash
export GITHUB_TOKEN=ghp_your_token_here   # classic token, `public_repo` scope is enough
python3 update_profile.py
```

The token is read only from the `GITHUB_TOKEN` environment variable. It is
never written to a file, never printed in logs, and must never be committed —
`.gitignore` already excludes `.env` files.

## Configuration

Edit only `config.json` — never the code — to change what the README says
and shows.

| Key | What it does | Default |
| --- | --- | --- |
| `username` | GitHub username to fetch | `abdulrahman-dogar-web` |
| `display_name` | Name shown in the header | `Mr. Abdul Rahman Dogar` |
| `bio` | Bio line under the header (falls back to your GitHub bio if empty) | Your GitHub bio |
| `tagline` | Short italic line under the bio | `Building in public — one project at a time.` |
| `location` | Location shown in the header (falls back to your GitHub location) | `Pakistan` |
| `website` | Personal website, shown in About if set | _(empty)_ |
| `max_repos` | How many repos appear in the Latest Projects table | `6` |
| `exclude_forks` | Hide forked repos from the table | `false` |
| `exclude_profile_repo` | Hide the repo named exactly like your username (your profile repo itself) | `true` |
| `exclude_archived` | Hide archived repos | `true` |
| `stats_theme` | Theme for the github-readme-stats cards (`tokyonight`, `dark`, `radical`, …) | `tokyonight` |
| `show_streak` | Include the GitHub streak card | `true` |
| `social` | `github`, `twitter`, `instagram`, `linkedin`, `youtube`, `website` — leave a field empty to hide that link | GitHub only |
| `sections` | Turn whole sections on/off: `header`, `badges`, `about`, `stats`, `languages`, `latest_projects`, `social`, `footer` | all `true` |

Unknown keys in `config.json` are ignored; missing keys fall back to the
built-in defaults in `update_profile.py`, so a partial config still works.

## Command-line options

```bash
python3 update_profile.py --help

python3 update_profile.py --output example/PROFILE_README.md   # write somewhere else
python3 update_profile.py --username octocat --max-repos 8     # another user, 8 repos
python3 update_profile.py --config my-config.json              # a different config file
python3 update_profile.py --dry-run                            # print to stdout, write nothing
```

Exit codes: `0` success · `1` config/usage error · `2` GitHub API error
(unknown user, bad token, rate limit exhausted after retries).

## How it works

```
config.json ──┐
              ▼
  update_profile.py ──► GET /users/{username}            (profile: name, bio,
              │              followers, created_at, hireable)
              ├──────────► GET /users/{username}/repos    (paginated, 100/page,
              │              sorted by updated_at, with retries)
              ▼
  filter (forks / archived / profile repo) → sort → take max_repos
              ▼
  render template → PROFILE_README.md (+ "last updated" timestamp)
```

- **Retries:** transient failures (HTTP 429, 502/503/504, network errors) are retried up to 4 times with exponential back-off. The GitHub API occasionally returns a 504 on the repos endpoint; the script recovers from that on its own.
- **Pagination:** every page of 100 repos is fetched, so accounts with more than 100 public repos work correctly.
- **Honest numbers:** descriptions come from the repo itself (`—` when a repo has none), star/fork counts come from the API, and language shares are counted from the fetched repos. Nothing is hard-coded or guessed.

## Automate it with GitHub Actions

`.github/workflows/update-profile.yml` is included and ready to use — no
editing needed. It:

1. Runs **every Monday at 00:00 UTC** (`cron: "0 0 * * 1"`), on every push that touches `update_profile.py`, `config.json`, or the workflow file itself, and on demand via **Actions → Update Profile README → Run workflow**.
2. Checks out the repo, sets up Python 3.12, installs `requirements.txt`.
3. Runs the script twice — once for `PROFILE_README.md`, once for `example/PROFILE_README.md` — using the built-in `secrets.GITHUB_TOKEN` (no personal token to create).
4. Commits and pushes the updated files **only if they changed** (commit message `chore: auto-update profile README [skip ci]`, so it never triggers itself in a loop).

To change the schedule, edit the `cron` line in that file — e.g. `"0 6 * * *"` for daily at 06:00 UTC, or `"0 0 1 * *"` for monthly.

## Use the generated file as your profile README

GitHub shows the README of a repository named exactly like your username
on your profile page. To use this output there:

1. Create a **new public repository** named exactly `abdulrahman-dogar-web` (your username).
2. Copy the generated `PROFILE_README.md` into it as `README.md` (rename it — GitHub only renders a file called `README.md`).
3. Commit and push. Your profile page at `github.com/abdulrahman-dogar-web` will show it immediately.
4. To keep it fresh, either re-run the script and copy the file again, or — better — add the workflow above to the profile repo as well and point its output at `README.md` (change `--output PROFILE_README.md` to `--output README.md` in the workflow).

## Troubleshooting

| Problem | Fix |
| --- | --- |
| `Not found (404)` | Check `username` in `config.json` — the account may not exist or may be renamed. |
| `Rate limit exceeded (403)` | Wait an hour, or set `GITHUB_TOKEN` (see above) for 5,000 requests/hour. |
| `Unauthorized (401)` | Your `GITHUB_TOKEN` is invalid or expired — generate a new one at GitHub → Settings → Developer settings → Personal access tokens. |
| Script succeeds but a stats card is blank | github-readme-stats / streak-stats are third-party image services — they render when GitHub loads the README; a blank card usually means the service is briefly down, not a bug in this script. |
| A new repo doesn't appear | Check `max_repos` (it may be cut off), `exclude_forks` (forks are hidden when `true`), and `exclude_profile_repo`. Then re-run. |
